# 4.2.3 Modelagem de Classes

## Dos substantivos às classes


| Substantivo | De onde veio | Vira | Por quê |
|---|---|---|---|
| soldado | ator da 4.2.2, HU01, HU02 | classe **Soldado** | o sistema registra quem solicita a manutenção e quem retira o equipamento |
| armeiro | ator da 4.2.2, HU03, HU04 | classe **Armeiro** | o responsável por executar o reparo e atualizar o acervo |
| nome, matricula | passo 1 do fluxo e cadastro | atributos de **Usuario** | soldado e armeiro possuem identificação única no quartel; o que é comum sobe para a classe geral |
| equipamento / DMT | passo 1, RF01, RF02 | classe **Equipamento** | a estrutura de DMT cadastrada no acervo com seu número de série e estado |
| item de estoque / insumo | passo 4 e 5, RF05 | classe **ItemEstoque** | o controle de lâminas e cilindros de gás disponíveis na oficina |
| manutenção / reparo | passo 3 e 7, RF04 | classe **Manutencao** | o registro do serviço executado, peças trocadas e data da intervenção |
| status / estado | passo 2, 6 e RF06 | atributo de **Equipamento** | indica se o DMT está disponível, em reparo ou bloqueado/danificado |
| oficina, balcão | contexto da 4.1 | nada | local físico e interface, estão fora do sistema de software |

## Classes

| Classe | Atributos | Operações | Veio de |
|---|---|---|---|
| **Usuario** | - nome: String, - matricula: String | + entrar(): boolean | RNF02 (autenticação de usuários no sistema) |
| **Soldado** | _herda de Usuario_ | + solicitarManutencao(): void | HU01, HU02 e RF03 |
| **Armeiro** | _herda de Usuario_ | _nenhuma própria_ | RNF02 (apenas armeiro altera status e registra manutenções) |
| **Equipamento** | - numeroSerie: String, - status: String, - dataUltimaRevisao: Data | + estaDisponivel(): boolean, + bloquear(): void | RF01, RF02, RF06 e passo 2 do fluxo principal |
| **ItemEstoque** | - nomeItem: String, - quantidade: int | + darBaixa(qtd: int): boolean, + repor(qtd: int): void | RF05, passo 5 do fluxo principal e A1 |
| **Manutencao** | - data: Data, - descricao: String, - tipoServico: String | + registrar(): void | RF04, RF07 e passos 3 e 7 do fluxo principal |

## Diagrama de classes

**Figura 1 – Diagrama de classes do DMTControl**

![Diagrama de classes do DMTControl](../diagramas/classes.png)

Fonte: Autoria própria (2026).

A Figura 1 apresenta a estrutura estática do DMTControl. A herança com triângulo vazado indica que **Soldado** e **Armeiro** são especializações da classe **Usuario**, compartilhando nome, matrícula e autenticação (`entrar()`).

O **Armeiro** registra zero ou várias **Manutencao** (associação `1` para `0..*`). Cada **Manutencao** está associada a exatamente um **Equipamento** (`1` para `1`) e consome zero ou vários **ItemEstoque** (`0..*` para `0..*`). O **Soldado** pode vincular solicitações a zero ou vários **Equipamento** (`1` para `0..*`).
